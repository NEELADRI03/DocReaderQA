# S0.3.3 — Protected routes and the current user

> **As a Dev, I want protected routes resolved to the current user, so that every query can be scoped by `user_id`.**

**Acceptance criteria:**
1. **A `get_current_user` dependency** turns the `Authorization: Bearer <access token>` header into a `User`.
2. **A missing or expired token returns 401**, in the standard error envelope.
3. **A test proves one user cannot read another user's collection.**

**Size:** S (half a day). Depends on S0.3.2, which must be merged first.

**Out of scope, don't build it yet:**
- **Creating, listing, renaming and deleting collections.** That's S1.1.1 and S1.1.2. This story adds only `GET /collections/{id}`, because criterion 3 needs a route that reads a collection. The tests insert collections straight into the table.
- **The frontend attaching the token and handling 401.** That's S0.4.1.
- **Postgres row-level security.** The architecture lists it as a second guard, after scoping in queries. It's a hardening task, not part of this story.
- **Roles or admin users.** Every user sees only their own data. Nobody sees everyone's.
- **A migration.** Nothing new is stored.

## Architecture

```
GET /api/v1/collections/{id}        Authorization: Bearer eyJhbGciOi...
         │
         ▼
┌─────────────────────────────────────────┐
│ api/router.py: protected router         │  every route in it depends on get_current_user,
│ dependencies=[Depends(get_current_user)]│  even one that forgets to ask for the user
└────────┬────────────────────────────────┘
         ▼
┌─────────────────────────────────────────┐  no header, or       ┌──────────────────────────────┐
│ api/deps.py: get_current_user()         │  not "Bearer ..." ──▶│ NOT_AUTHENTICATED → 401      │
│ 1. HTTPBearer reads the header          │                      │ WWW-Authenticate: Bearer     │
│ 2. decode_token(token, "access")        │  bad, expired, or    │                              │
│ 3. session.get(User, user_id)           │  refresh token,  ───▶│ INVALID_TOKEN → 401          │
└────────┬────────────────────────────────┘  or user deleted     │ WWW-Authenticate: Bearer     │
         │ User                                                  │   error="invalid_token"      │
         ▼                                                       └──────────────────────────────┘
┌─────────────────────────────────────────┐
│ api/collections.py: get_collection()    │  not found, or       ┌──────────────────────────────┐
│ SELECT ... WHERE id = :id               │  someone else's ────▶│ COLLECTION_NOT_FOUND → 404   │
│              AND user_id = :current     │                      └──────────────────────────────┘
└────────┬────────────────────────────────┘
         ▼
{"id": "...", "name": "Contracts", "created_at": "..."}
```

**Two layers, each with one job.**
- `get_current_user` answers "who is calling?". It runs once per request, before the route, and anything it rejects never reaches the route.
- The route answers "what may they see?". It puts `user.id` in the `WHERE` clause. That's the "scoped by `user_id`" in the story. Every later route that reads documents, chunks or conversations follows the same pattern.

## Step 1 — `app/api/deps.py`: the current user

This new module holds what every router shares. `Session` and `BEARER` move here from `auth.py`, because `collections.py` needs them too.

```python
from typing import Annotated

from fastapi import Depends, status
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from sqlalchemy.ext.asyncio import AsyncSession

from app.api.errors import ApiError
from app.db.models import User
from app.db.session import get_session
from app.tokens import InvalidTokenError, decode_token

Session = Annotated[AsyncSession, Depends(get_session)]

# RFC 9110: a 401 must name the scheme. RFC 6750 adds error="invalid_token" when a token was sent.
BEARER = {"WWW-Authenticate": "Bearer"}
INVALID_BEARER = {"WWW-Authenticate": 'Bearer error="invalid_token"'}

# auto_error=False: a missing or non-Bearer header comes back as None, so we answer with our
# own envelope and a 401. Also puts the Authorize button in /docs.
bearer_scheme = HTTPBearer(auto_error=False)

Credentials = Annotated[HTTPAuthorizationCredentials | None, Depends(bearer_scheme)]


async def get_current_user(credentials: Credentials, session: Session) -> User:
    """The user the access token belongs to, or a 401."""
    if credentials is None:
        raise ApiError(
            status.HTTP_401_UNAUTHORIZED,
            "NOT_AUTHENTICATED",
            "Send an access token in the Authorization header.",
            headers=BEARER,
        )

    invalid = ApiError(
        status.HTTP_401_UNAUTHORIZED,
        "INVALID_TOKEN",
        "The access token is invalid or has expired.",
        headers=INVALID_BEARER,
    )
    try:
        user_id = decode_token(credentials.credentials, "access")
    except InvalidTokenError as exc:
        raise invalid from exc

    # The account may have been deleted since the token was issued
    user = await session.get(User, user_id)
    if user is None:
        raise invalid
    return user


CurrentUser = Annotated[User, Depends(get_current_user)]
```

### How the code works

- **`HTTPBearer` reads the header.** It splits `Authorization: Bearer <token>` and gives back the token in `credentials.credentials`. It also registers a security scheme in the OpenAPI schema, which is what puts the **Authorize** button in `/docs` (Step 7).
- **`auto_error=False` is deliberate.** With the default `True`, `HTTPBearer` raises its own `HTTPException`. Which status that uses has changed between FastAPI versions: older ones send 403, newer ones 401. It also can't carry our `NOT_AUTHENTICATED` code. With `False`, a missing header, or one with another scheme such as `Basic`, comes back as `None`, and we raise our own `ApiError`.
- **`decode_token(..., "access")`** is the S0.3.2 function. It checks the signature, the expiry, and that `type` is `access`. A refresh token, which lives 7 days, is rejected here, so it can never open an API route.
- **One database lookup per request.** The token alone proves the user existed when it was issued. `session.get(User, user_id)` is a primary-key lookup (well under a millisecond on a warm pool). It makes a deleted account lose access at once, instead of up to 30 minutes later. Routes also get a real `User` object, not just an ID.
- **Two codes, both 401.**
  - `NOT_AUTHENTICATED`: no token was sent. The client should log in.
  - `INVALID_TOKEN`: a token was sent, but it's bad, expired, of the wrong type, or its user is gone. The client should refresh, and log in if the refresh also fails.

  The frontend (S0.4.1) can treat any 401 the same way. The two codes just make logs and debugging clearer.
- **`error="invalid_token"` in the header** is what RFC 6750 §3.1 asks for when a token was sent but is bad. When no token was sent, the RFC says to leave the error out, so `NOT_AUTHENTICATED` sends plain `Bearer`.
- **`CurrentUser`** is the type alias routes use, the same way `Session` is: `user: CurrentUser`.
- **`decode_token` runs before the database is touched.** `get_session` opens a session but doesn't connect until the first query. A bad token is rejected without a database round trip, and the tests for it run without Postgres.

## Step 2 — `GET /collections/{collection_id}`

### `app/schemas/collections.py` (new)

```python
import uuid
from datetime import datetime

class CollectionRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: uuid.UUID
    name: str
    created_at: datetime
```

`user_id` is left out. The caller is always the owner, so it would only repeat their own ID.

### `app/api/collections.py` (new)

```python
import uuid

from fastapi import APIRouter, status
from sqlalchemy import select

from app.api.deps import CurrentUser, Session
from app.api.errors import ApiError, ErrorResponse
from app.db.models import Collection
from app.schemas.collections import CollectionRead

router = APIRouter(prefix="/collections", tags=["collections"])


@router.get(
    "/{collection_id}",
    responses={401: {"model": ErrorResponse}, 404: {"model": ErrorResponse}},
)
async def get_collection(
    collection_id: uuid.UUID, user: CurrentUser, session: Session
) -> CollectionRead:
    # The owner check is part of the query, so another user's collection is never loaded
    collection = await session.scalar(
        select(Collection).where(Collection.id == collection_id, Collection.user_id == user.id)
    )
    if collection is None:
        # 404, not 403: a 403 would confirm that the ID exists for somebody else
        raise ApiError(
            status.HTTP_404_NOT_FOUND, "COLLECTION_NOT_FOUND", "The collection does not exist."
        )
    return CollectionRead.model_validate(collection)
```

### How the code works

- **Scope in the query, not after it.** The other way is `session.get(Collection, id)` followed by `if collection.user_id != user.id`. That works, until someone writes a new route and forgets the `if`. With the owner in the `WHERE` clause, the row for another user is never loaded, so there's nothing to leak. This is the pattern for every query on user data from now on: documents, chunks and conversations all have a `user_id` column for exactly this.
- **404 for someone else's collection, not 403.** A 403 would tell Bob "this ID exists, it's just not yours". With a 404, he can't tell Ann's collection from an ID that doesn't exist. The test checks that both responses are identical.
- **`collection_id: uuid.UUID`** makes FastAPI reject `/collections/abc` with a 422 `VALIDATION_ERROR` before the query runs. Auth still comes first: without a token, `/collections/abc` gets the 401 (shown in Step 7).
- **S1.1.1 builds on this.** It adds `GET /collections` (list), `POST` and `PATCH` to the same router, each scoped the same way.

## Step 4 — `app/api/router.py`: protected by default

```python
from fastapi import APIRouter, Depends

from app.api import auth, collections, health
from app.api.deps import get_current_user

api_router = APIRouter(prefix="/api/v1")

# Public: no token needed
api_router.include_router(health.router)
api_router.include_router(auth.router)

# Everything included here needs a valid access token, even a route that forgets CurrentUser.
# FastAPI runs get_current_user once per request, however many times it's declared.
protected = APIRouter(dependencies=[Depends(get_current_user)])
protected.include_router(collections.router)
api_router.include_router(protected)
```

### How the code works

- **The architecture says every route except auth and health needs a token.** Here that becomes structural. A new router goes under `protected`, and its routes need a token whether or not they ask for `CurrentUser`. A route that needs the user's ID still declares `user: CurrentUser` to get it.
- **No double work.** FastAPI caches a dependency's result for the length of one request. `get_current_user` on the router plus `user: CurrentUser` on the route still means one token check and one `SELECT`. I checked this with a counting override: one call per request.
- **I also checked the safety net.** A route under `protected` that doesn't mention `CurrentUser` at all still answers 401 without a token.

**Record these in your decision log:**
- **Routes are protected by default.** New routers go under the `protected` router. Only `health` and `auth` are public, and `test_every_other_route_needs_a_token` enforces that (Step 5).
- **`get_current_user` loads the user from the database on every request.** One primary-key lookup buys instant lockout of deleted accounts, and gives routes a real `User`.
- **Queries are scoped in SQL** (`WHERE user_id = :current_user`), never by loading a row and comparing afterwards.
- **Another user's resource is a 404, not a 403**, so IDs from other accounts can't be confirmed.
- **401 codes:** `NOT_AUTHENTICATED` when no token is sent, `INVALID_TOKEN` when the token is bad, expired, of the wrong type, or its user is deleted.

### `tests/test_protected_routes.py` (new)

```python

import uuid
from datetime import UTC, datetime, timedelta

import httpx2
import jwt
import pytest
from sqlalchemy import delete
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker

from app.config import get_settings
from app.db.models import Collection, User
from app.main import app
from app.tokens import ALGORITHM, create_token

pytestmark = pytest.mark.anyio

ME = "/api/v1/auth/me"

# Every other route under /api/v1 must answer 401 without a token
PUBLIC_ROUTES = {
    ("GET", "/api/v1/health"),
    ("POST", "/api/v1/auth/register"),
    ("POST", "/api/v1/auth/login"),
    ("POST", "/api/v1/auth/refresh"),
}

NOT_AUTHENTICATED = {
    "error": {
        "code": "NOT_AUTHENTICATED",
        "message": "Send an access token in the Authorization header.",
    }
}
INVALID_TOKEN = {
    "error": {"code": "INVALID_TOKEN", "message": "The access token is invalid or has expired."}
}
COLLECTION_NOT_FOUND = {
    "error": {"code": "COLLECTION_NOT_FOUND", "message": "The collection does not exist."}
}


def bearer(token: str) -> dict[str, str]:
    return {"Authorization": f"Bearer {token}"}


def expired_access_token() -> str:
    past = datetime.now(UTC) - timedelta(minutes=1)
    claims = {"sub": str(uuid.uuid4()), "type": "access", "exp": past}
    return jwt.encode(claims, get_settings().jwt_secret.get_secret_value(), algorithm=ALGORITHM)


async def add_user(sessions: async_sessionmaker[AsyncSession]) -> User:
    # Straight into the table: these tests are about tokens, not passwords
    async with sessions() as session:
        user = User(email=f"{uuid.uuid4().hex[:12]}@example.com")
        session.add(user)
        await session.commit()
    return user


async def add_collection(sessions: async_sessionmaker[AsyncSession], owner: User) -> Collection:
    async with sessions() as session:
        collection = Collection(user_id=owner.id, name="Contracts")
        session.add(collection)
        await session.commit()
    return collection


# --- Rejected before the database is touched ------------------------------------


async def test_missing_token_is_401(client: httpx2.AsyncClient) -> None:

    assert response.status_code == 401
    assert response.json() == NOT_AUTHENTICATED

    assert response.json() == INVALID_TOKEN

def _protected_routes() -> list[tuple[str, str]]:
    # Read from the OpenAPI schema: every route the API documents, with its full path
    paths: dict[str, dict[str, object]] = app.openapi()["paths"]
    routes = [(method.upper(), path) for path, ops in paths.items() for method in ops]
    protected = [route for route in routes if route not in PUBLIC_ROUTES]
    assert protected, "found no protected routes; is the route listing broken?"
    return protected


@pytest.mark.parametrize(("method", "path"), _protected_routes())
async def test_every_other_route_needs_a_token(
    client: httpx2.AsyncClient, method: str, path: str
) -> None:
    # Fill path parameters such as {collection_id} with a well-formed ID
    url = re.sub(r"\{[^}]+\}", str(uuid.uuid4()), path)

    response = await client.request(method, url)

    assert response.status_code == 401, f"{method} {path} answered without a token"

    bob = await add_user(sessions)
    anns_collection = await add_collection(sessions, ann)

    someone_elses = await client.get(
        f"/api/v1/collections/{anns_collection.id}", headers=bobs_token

    nonexistent = await client.get(f"/api/v1/collections/{uuid.uuid4()}", headers=bobs_token)
```

### How the tests work

- **`test_user_cannot_read_another_users_collection` is acceptance criterion 3.** Bob holds a valid token and asks for Ann's collection by its real ID. He gets the same 404, with the same body, as for a random ID.
- **The first five tests need no database.** A missing, garbage, expired or refresh token is rejected before `get_current_user` queries anything, so these run in CI's quick path and on your machine without Postgres.
- **`test_every_other_route_needs_a_token` is the safety net for later stories.** It lists every route in the OpenAPI schema and calls each one without a token. Any route that isn't in `PUBLIC_ROUTES` must answer 401. Right now that's `GET /auth/me` and `GET /collections/{collection_id}`. When S1.1.1 adds `POST /collections`, it's checked automatically, and if someone puts a new router on `api_router` instead of `protected` and forgets `CurrentUser`, this test fails.
  - **Why the OpenAPI schema, not `app.routes`.** In FastAPI 0.143 (your version), `app.routes` holds the included routers as one lazy `_IncludedRouter` object, not as individual routes. A loop over it finds nothing, and the parametrized test silently skips with "got empty parameter set". The OpenAPI schema is public API and lists every documented route with its full path. The `assert protected` line makes an empty list fail loudly instead of skipping.
  - **The one gap:** a route declared with `include_in_schema=False` isn't in the schema, so the audit can't see it. Don't hide routes under `/api/v1`.
- **Users are inserted straight into the table** (`add_user`), with no password. These tests are about tokens, and skipping registration avoids one argon2 hash (~80 ms) per user. `test_auth.py` already covers the register-then-login flow end to end.
- **`expired_access_token()` signs a token by hand** with an `exp` in the past, the same way `test_tokens.py` does, because `create_token` can't make an expired one.

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| 403 `{"error": {"code": "FORBIDDEN", "message": "Not authenticated"}}` with no token | `HTTPBearer()` without `auto_error=False`, on a FastAPI version that answers 403 | `HTTPBearer(auto_error=False)` (Step 1) |
| 401 `UNAUTHORIZED` / `"Not authenticated"` instead of `NOT_AUTHENTICATED` | Same, on a FastAPI version that answers 401 | Same |
| `test_every_other_route_needs_a_token` is skipped: "got empty parameter set" | Routes listed from `app.routes`, which FastAPI 0.143 no longer flattens | List them from `app.openapi()["paths"]` (Step 5) |
| A route answers 200 without a token | Its router was included on `api_router`, not on `protected`, and the route doesn't take `CurrentUser` | `protected.include_router(...)` (Step 4); the audit test catches this |
| `fixture 'client' not found` in `test_protected_routes.py` | The fixtures are still in `test_auth.py` | Move them to `conftest.py` (Step 5) |
| `ValidationError: database_url` or `jwt_secret` when collecting tests | `import app...` at the top of `conftest.py`, before the env lines | Import inside the fixtures (Step 5) |
| Refresh tests fail: `INVALID_CREDENTIALS` != `INVALID_TOKEN` | Step 0, fix 1 | `"INVALID_TOKEN"` in `refresh()` |
| `test_invalid_login_input_...[body3-password]` fails with 401, not 422 | Step 0, fix 2 | `Field(max_length=PASSWORD_MAX_LENGTH, repr=False)` |
| `password authentication failed for user "docqa"` (or `"test"`) in DB tests | `TEST_DATABASE_URL` points at port 5432: the native Postgres, not Docker | Use port 5433 (Step 8) |
| Every protected call returns `INVALID_TOKEN` right after login | Sending the refresh token, or the API restarted with a different `JWT_SECRET` | Send `access_token`; keep one fixed secret in `.env` |
| `INVALID_TOKEN` after about 30 minutes | The access token expired, which is expected | `POST /auth/refresh` for a new pair; S0.4.1 automates this |
| Bob gets 200 for Ann's collection | The query loads by ID only and forgets `Collection.user_id == user.id` | Scope in the `WHERE` (Step 2) |
| Swagger's **Authorize** sends `Bearer Bearer eyJ...` | Pasted the token with the `Bearer ` prefix | Paste the token alone |
