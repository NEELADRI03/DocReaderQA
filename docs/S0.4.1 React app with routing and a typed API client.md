## Architecture

```
Browser, http://localhost:5173                              API, http://localhost:8000
┌────────────────────────────────────────────┐
│ main.tsx                                   │
│  QueryClientProvider    (server data cache)│
│   RouterProvider        (URL → page)       │
│    /login     LoginPage                    │
│    (layout)   RequireAuth ── no tokens? ───┼──▶ <Navigate to="/login">
│      /        HomePage                     │
└───────────────┬────────────────────────────┘
                │ useQuery(meQuery)
                ▼
┌────────────────────────────────────────────┐   GET /api/v1/auth/me
│ lib/api.ts   api<T>(path, options)         │   Authorization: Bearer <access>
│ 1. adds the access token from tokens.ts    ├──────────────────────────────▶ 200 {id, email, ...}
│ 2. 401? POST /auth/refresh once, save the  │                                 401 INVALID_TOKEN
│    new pair, repeat the call               │
│ 3. refresh 401 too? clear the tokens and   │──▶ onSessionExpired()
│    end the session                         │     router.tsx: clear the cache, go to /login
│ 4. any error → ApiError(status, code, ...) │
└────────────────────────────────────────────┘
```

**Each piece has one job.**
- `tokens.ts` stores the tokens and knows nothing about HTTP.
- `api.ts` does HTTP and knows nothing about React or the router. When a session ends it calls a handler, and `router.tsx` decides what that means.
- `auth.ts` holds the auth calls and the `meQuery` that pages share.
- `RequireAuth` keeps logged-out users away from the app's pages.

Later stories add files such as `lib/collections.ts` with their own `queryOptions`, and they get the token, refresh and error handling without doing anything.

## Step 1 — Backend: allow the browser to call the API (CORS)

The React app runs at `http://localhost:5173` and the API at `http://localhost:8000`. Different ports make them different **origins**, so the browser blocks the app's calls unless the API says that origin is allowed. That permission is CORS.

`app/config.py` already has `cors_origins` (default `http://localhost:5173`), and `.env.example` has `CORS_ORIGINS`. But nothing uses the setting yet. Right now, every call from the app fails in the browser with *"blocked by CORS policy"*.

### `app/main.py`

Replace the file with this. The commented-out health route that was left in it goes too, because `app/api/health.py` replaced it in S0.2.1.

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.api.errors import register_error_handlers
from app.api.router import api_router
from app.config import get_settings
from app.db.session import engine


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    yield
    await engine.dispose()


app = FastAPI(title="DocQA API", lifespan=lifespan)
register_error_handlers(app)

# The React app runs on another origin (localhost:5173), so the browser asks before each call.
# Tokens travel in the Authorization header, not cookies, so credentials stay off.
app.add_middleware(
    CORSMiddleware,
    allow_origins=get_settings().cors_origins,
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
)

app.include_router(api_router)
```

### How the code works

- **The preflight.** Before a call with an `Authorization` header or a JSON body, the browser first sends an `OPTIONS` request (the "preflight") that asks: may `http://localhost:5173` send a `GET` with an `authorization` header? `CORSMiddleware` answers it directly. It never reaches your routes or `get_current_user`, so the preflight doesn't need a token.
- **Exact origins, from config.** `allow_origins` is the `CORS_ORIGINS` list, never `["*"]`. In production you set it to the real frontend URL.
- **`allow_credentials` stays off** (its default). It's only needed for cookies, and the tokens travel in a header.
- **The headers we send:** `Authorization` for the token and `Content-Type: application/json` for bodies. The methods are the four the API uses.
- **Error responses carry the CORS header too.** The middleware wraps the whole app, including the error handlers. That matters: without `Access-Control-Allow-Origin` on a 401, the browser hides the response from the app, which then can't tell it to go to the login page. The third test checks this.
- **One gap:** an unhandled exception (a real 500) is answered outside the middleware, so it has no CORS header. The browser reports it as a network error. That's acceptable, because a 500 is a bug to fix in the logs anyway.

### `tests/test_cors.py` (new)

```python
from fastapi.testclient import TestClient

from app.main import app

client = TestClient(app)

FRONTEND = "http://localhost:5173"
ME = "/api/v1/auth/me"


def preflight(origin: str) -> dict[str, str]:
    return {
        "Origin": origin,
        "Access-Control-Request-Method": "GET",
        "Access-Control-Request-Headers": "authorization",
    }


def test_preflight_from_the_frontend_is_allowed() -> None:
    # The browser sends this before any call that carries an Authorization header
    response = client.options(ME, headers=preflight(FRONTEND))

    assert response.status_code == 200
    assert response.headers["access-control-allow-origin"] == FRONTEND
    assert "authorization" in response.headers["access-control-allow-headers"].lower()


def test_preflight_from_another_origin_is_refused() -> None:
    response = client.options(ME, headers=preflight("https://evil.example"))

    assert response.status_code == 400
    assert "access-control-allow-origin" not in response.headers


def test_error_responses_carry_the_cors_header() -> None:
    # Without it, the browser hides the 401 from the app, which then can't redirect to login
    response = client.get(ME, headers={"Origin": FRONTEND})

    assert response.status_code == 401
    assert response.headers["access-control-allow-origin"] == FRONTEND
```

None of the three tests need a database. The 401 is decided before `get_current_user` queries anything.

## Step 3 — `src/lib/tokens.ts`: where the tokens live

```ts
// Where the JWTs live between page loads. One key, so they're written and cleared together.
const STORAGE_KEY = 'docqa.tokens'

export interface Tokens {
  accessToken: string
  refreshToken: string
}

// The body of POST /auth/login and POST /auth/refresh
export interface TokenResponse {
  access_token: string
  refresh_token: string
  token_type: 'bearer'
  expires_in: number
}

export function getTokens(): Tokens | null {
  const raw = localStorage.getItem(STORAGE_KEY)
  if (raw === null) return null
  try {
    return JSON.parse(raw) as Tokens
  } catch {
    // Someone edited it by hand; treat it as logged out
    return null
  }
}

export function saveTokens(response: TokenResponse): void {
  const tokens: Tokens = {
    accessToken: response.access_token,
    refreshToken: response.refresh_token,
  }
  localStorage.setItem(STORAGE_KEY, JSON.stringify(tokens))
}

export function clearTokens(): void {
  localStorage.removeItem(STORAGE_KEY)
}
```

### Where the tokens live: the decision S0.3.2 left for this story

| Option | Survives a page reload | Readable by injected scripts (XSS) | Backend changes |
|---|---|---|---|
| Memory only | No: every reload logs you out | No | None |
| **`localStorage`** (chosen) | **Yes** | **Yes** | **None** |
| httpOnly cookie set by the API | Yes | No | Cookie endpoints, CSRF protection, `allow_credentials` |

- **`localStorage` is chosen for v1.** It keeps you logged in across reloads with no backend changes. The risk: if an attacker ever got script into the page (XSS), they could read the tokens. React escapes everything it renders, the app shows no user-supplied HTML yet, and an access token lives 30 minutes.
- **Revisit before production.** The architecture plans markdown rendering of answers in Phase 2, and that's where XSS risk appears. Moving the refresh token to an httpOnly cookie is a Phase 4 hardening task. Only `tokens.ts` and the refresh call change.
- **Both tokens go under one key**, so they can never get out of step: one written and the other not.

## Step 4 — `src/lib/api.ts`: the API client

```ts
import { clearTokens, getTokens, saveTokens, type TokenResponse } from './tokens'

export const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:8000/api/v1'

export interface FieldError {
  field: string
  message: string
}

// Every failed call becomes one of these, built from the backend's error envelope:
// {"error": {"code": "...", "message": "...", "details": [...]}}
export class ApiError extends Error {
  readonly status: number
  readonly code: string
  readonly details: FieldError[]

  constructor(status: number, code: string, message: string, details: FieldError[] = []) {
    super(message)
    this.name = 'ApiError'
    this.status = status
    this.code = code
    this.details = details
  }
}

export interface RequestOptions {
  method?: 'GET' | 'POST' | 'PATCH' | 'DELETE'
  // Sent as JSON
  body?: unknown
  // false for login, register and refresh: no token is sent, and a 401 is just an error
  auth?: boolean
  signal?: AbortSignal
}

// Called when the session is over: the refresh token was rejected too.
// router.tsx sets it to "go to /login", so this file doesn't depend on the router.
let onSessionExpired: () => void = () => {}

export function setSessionExpiredHandler(handler: () => void): void {
  onSessionExpired = handler
}

export async function api<T>(path: string, options: RequestOptions = {}): Promise<T> {
  const auth = options.auth ?? true
  let response = await send(path, options, auth)

  if (response.status === 401 && auth) {
    // The access token expired (it lives 30 minutes). Swap the refresh token for a new pair once.
    if (await refreshTokens()) {
      response = await send(path, options, auth)
    }
    if (response.status === 401) {
      clearTokens()
      onSessionExpired()
    }
  }

  if (!response.ok) {
    throw await toApiError(response)
  }
  if (response.status === 204) {
    return undefined as T
  }
  return (await response.json()) as T
}

async function send(path: string, options: RequestOptions, auth: boolean): Promise<Response> {
  const headers = new Headers()
  if (options.body !== undefined) {
    headers.set('Content-Type', 'application/json')
  }
  const tokens = auth ? getTokens() : null
  if (tokens) {
    headers.set('Authorization', `Bearer ${tokens.accessToken}`)
  }

  try {
    return await fetch(`${API_BASE_URL}${path}`, {
      method: options.method ?? 'GET',
      headers,
      body: options.body === undefined ? undefined : JSON.stringify(options.body),
      signal: options.signal,
    })
  } catch (error) {
    // Cancelled on purpose: let the caller (TanStack Query) see the AbortError
    if (error instanceof DOMException && error.name === 'AbortError') throw error
    // fetch only throws when there's no HTTP response at all: API down, DNS, or CORS refused
    throw new ApiError(0, 'NETWORK_ERROR', 'Could not reach the server. Is the API running?')
  }
}

// Several calls can get a 401 at the same moment. They all wait for one refresh, because the
// first refresh would otherwise race the others with the same refresh token.
let refreshInFlight: Promise<boolean> | null = null

function refreshTokens(): Promise<boolean> {
  refreshInFlight ??= doRefresh().finally(() => {
    refreshInFlight = null
  })
  return refreshInFlight
}

async function doRefresh(): Promise<boolean> {
  const tokens = getTokens()
  if (!tokens) return false

  const response = await send(
    '/auth/refresh',
    { method: 'POST', body: { refresh_token: tokens.refreshToken } },
    false,
  )
  if (!response.ok) return false

  saveTokens((await response.json()) as TokenResponse)
  return true
}

async function toApiError(response: Response): Promise<ApiError> {
  try {
    const { error } = (await response.json()) as {
      error: { code: string; message: string; details?: FieldError[] }
    }
    return new ApiError(response.status, error.code, error.message, error.details)
  } catch {
    // Not our envelope: a proxy error page, or an empty body
    return new ApiError(response.status, 'HTTP_ERROR', `Request failed (${response.status})`)
  }
}
```

### How the code works

- **`api<T>()` is the only place that calls `fetch`.** Pages never call `fetch` themselves. That's what lets later features "plug in cleanly": each new endpoint is one line, such as `api<Collection[]>('/collections')`, and it gets the token, refresh and error handling for free.
- **`T` is a promise, not a check.** `api<User>('/auth/me')` tells TypeScript what the JSON will look like, but nothing verifies it at runtime. The types are written by hand to match the backend's Pydantic schemas. If the two drift apart, TypeScript won't notice. Generating types from `/openapi.json` (for example with `openapi-typescript`) is a later option once there are more endpoints.
- **A 401 is handled in three steps** (acceptance criterion 4):
  1. The access token expired: it lives 30 minutes (S0.3.2). The client sends the refresh token to `POST /auth/refresh` and gets a new pair.
  2. It repeats the original call once with the new access token. The user never notices.
  3. If the refresh is rejected too (7 days have passed, or the user was deleted), or the repeated call still gets 401, the session is over. The client clears the tokens and calls `onSessionExpired`, which goes to `/login` (Step 6).
- **One refresh at a time.** When the token expires, the page may have three queries in flight, and all three get a 401. Without `refreshInFlight`, each would start its own refresh. With it, the first starts the refresh and the others wait for the same promise. `??=` assigns only when the variable is still `null`, and `finally` resets it for the next expiry. The test "shares one refresh..." fails if you change `??=` to `=`.
- **`auth: false` for login, register and refresh.** Those don't send a token. A 401 from login means "wrong password", not "session expired", so it must not trigger a refresh or a redirect. It just becomes an `ApiError` the login form shows.
- **Every failure is an `ApiError`** with the HTTP status, the backend's `code` and `message`, and `details` for 422 field errors (S0.3.1's envelope). Forms in S0.4.2 use `details` to put each message under its field.
- **No HTTP response at all becomes `NETWORK_ERROR`** (status 0): the API is down, the URL is wrong, or CORS refused. The browser deliberately gives no detail, so the message suggests the most likely cause.
- **An `AbortError` is passed through unchanged.** TanStack Query cancels a query when its page unmounts, by aborting the `signal`. Treating that as a network error would show a false error.
- **`API_BASE_URL`** comes from `VITE_API_BASE_URL`. In Docker, Compose passes it from `.env` (`env_file` on the `frontend` service, set up in S0.1.1). Outside Docker, it falls back to the local API.

**The API client doesn't import the router.** `onSessionExpired` is a handler that `router.tsx` installs. That avoids a circular import, and it lets tests check the client's behaviour on its own.

## Step 5 — `src/lib/auth.ts` and `src/lib/queryClient.ts`

### `src/lib/auth.ts`

```ts
import { queryOptions } from '@tanstack/react-query'

import { api } from './api'
import { clearTokens, saveTokens, type TokenResponse } from './tokens'

// GET /auth/me and POST /auth/register return this (UserRead in the backend)
export interface User {
  id: string
  email: string
  created_at: string
}

export async function login(email: string, password: string): Promise<void> {
  const tokens = await api<TokenResponse>('/auth/login', {
    method: 'POST',
    body: { email, password },
    auth: false,
  })
  saveTokens(tokens)
}

export function register(email: string, password: string): Promise<User> {
  return api<User>('/auth/register', { method: 'POST', body: { email, password }, auth: false })
}

// v1 has no server-side logout: the tokens are stateless JWTs, so forgetting them is the logout
export function logout(): void {
  clearTokens()
}

// "Who is logged in?" Every component that needs the user calls useQuery(meQuery),
// so they share one cache entry and one request.
export const meQuery = queryOptions({
  queryKey: ['auth', 'me'],
  queryFn: ({ signal }) => api<User>('/auth/me', { signal }),
  // The user doesn't change while logged in; logout clears the whole cache
  staleTime: Infinity,
})
```

- **`queryOptions`** bundles a query's key, fetch function and settings into one typed object. `useQuery(meQuery)` in any component reads the same cache entry, and TypeScript knows `data` is a `User`. Every later feature follows this pattern, for example `collectionsQuery` in S1.1.1.
- **`signal`** is passed through to `fetch`, so TanStack Query can cancel the request (see `AbortError` in Step 4).
- **`staleTime: Infinity`:** the logged-in user doesn't change, so it's fetched once per session, not on every window focus.

### `src/lib/queryClient.ts`

```ts
import { QueryClient } from '@tanstack/react-query'

import { ApiError } from './api'

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      // Retry network blips and 5xx, but not 4xx: asking again won't fix a 404 or a 422
      retry: (failureCount, error) => {
        if (error instanceof ApiError && error.status >= 400 && error.status < 500) return false
        return failureCount < 2
      },
    },
  },
})
```

TanStack Query retries a failed query 3 times by default. That helps with a dropped connection or a restarting API, but it's wasted work for a 404 or 422, which would fail the same way again. A 401 never reaches this function: the API client has already refreshed, or ended the session.

## Step 6 — Routing: `router.tsx`, `RequireAuth`, and two placeholder pages

### `src/router.tsx` (new)

```tsx
import type { QueryClient } from '@tanstack/react-query'
import { Navigate, type createBrowserRouter, type RouteObject } from 'react-router'

import { setSessionExpiredHandler } from './lib/api'
import HomePage from './routes/HomePage'
import LoginPage from './routes/LoginPage'
import RequireAuth from './routes/RequireAuth'

export const routes: RouteObject[] = [
  { path: '/login', element: <LoginPage /> },
  {
    // No path: a layout route. Every child needs a logged-in user.
    element: <RequireAuth />,
    children: [{ index: true, element: <HomePage /> }],
  },
  { path: '*', element: <Navigate to="/" replace /> },
]

type AppRouter = ReturnType<typeof createBrowserRouter>

// What happens when even the refresh token is rejected. A function, not top-level code,
// so tests can connect it to their own memory router.
export function handleSessionExpiry(router: AppRouter, queryClient: QueryClient): void {
  setSessionExpiredHandler(() => {
    // Drop the old user's cached data before anyone else logs in
    queryClient.clear()
    void router.navigate('/login', { replace: true, state: { from: router.state.location } })
  })
}
```

- **Data mode** (`createBrowserRouter` plus `RouterProvider`). React Router 8 has three modes: declarative (`<BrowserRouter>`), data, and framework (its own build tool, for server rendering). Data mode suits a Vite SPA. It also gives you `router.navigate()` for code outside components, which `handleSessionExpiry` needs.
- **A layout route** has an element but no path. `RequireAuth` wraps every route inside it, so a new logged-in page goes in `children` and is protected without any extra code. It's the same idea as S0.3.3's `protected` router.
- **`*`** catches any unknown URL and sends it to `/`. From there, `RequireAuth` sends logged-out users on to `/login`.
- **`state: { from }`** remembers where the user was, so login can send them back there.
- **`queryClient.clear()`** on expiry, so data cached for one user can never show up for the next.
- **`routes` is exported**, so tests mount the same routes in a memory router (Step 7).

### `src/routes/RequireAuth.tsx` (new)

```tsx
import { useQuery } from '@tanstack/react-query'
import { Navigate, Outlet, useLocation } from 'react-router'

import { meQuery } from '../lib/auth'
import { getTokens } from '../lib/tokens'

// Wraps every page that needs a logged-in user
export default function RequireAuth() {
  const location = useLocation()
  const hasTokens = getTokens() !== null

  // Asks "is the token still good, and whose is it?" once; pages read the user from the cache
  const me = useQuery({ ...meQuery, enabled: hasTokens })

  if (!hasTokens) {
    // Remember where the user was going, so login can send them back
    return <Navigate to="/login" replace state={{ from: location }} />
  }
  if (me.isPending) {
    return <p role="status">Loading…</p>
  }
  if (me.isError) {
    // A 401 never gets here: the API client has already sent the user to /login
    return (
      <div role="alert">
        <p>{me.error.message}</p>
        <button type="button" onClick={() => void me.refetch()}>
          Try again
        </button>
      </div>
    )
  }
  return <Outlet />
}
```

There are two ways a user gets sent to `/login`:

| Situation | Who notices | How |
|---|---|---|
| No tokens at all (first visit, or after logout) | `RequireAuth` | `<Navigate to="/login">`, with no API call |
| Tokens present but dead (expired refresh token, deleted user) | The API client, on `GET /auth/me` | refresh fails → `onSessionExpired` → `router.navigate('/login')` |

**Why call `/auth/me` at all, when the tokens are already there?** Their presence proves nothing: they may have expired days ago. One `/auth/me` on load either confirms the session (refreshing it if needed) or ends it, before the page shows anything. S0.3.3 added the route for exactly this. Other errors, such as the API being down, show a message and **Try again** instead of logging the user out.

`<Outlet />` renders the matched child route, here `HomePage`.

```ts
import { vi } from 'vitest'

import { API_BASE_URL } from '../lib/api'
import type { User } from '../lib/auth'
import type { TokenResponse } from '../lib/tokens'

export const USER: User = { id: '1', email: 'ann@example.com', created_at: '2026-11-25T10:00:00Z' }
export const TOKENS: TokenResponse = {
  access_token: 'a',
  refresh_token: 'r',
  token_type: 'bearer',
  expires_in: 1800,
}

export function json(status: number, body: unknown): Response {
  return new Response(JSON.stringify(body), {
    status,
    headers: { 'Content-Type': 'application/json' },
  })
}

type Handler = (init: RequestInit | undefined) => Response

// Replaces fetch with a fake API. Keys look like "POST /auth/login".
// A call with no handler fails the test, so nothing reaches a real server by accident.
export function fakeApi(handlers: Record<string, Handler>) {
  const fetchMock = vi.fn<typeof fetch>(async (input, init) => {
    const path = String(input).slice(API_BASE_URL.length)
    const key = `${init?.method ?? 'GET'} ${path}`
    const handler = handlers[key]
    if (!handler) throw new Error(`Unexpected API call: ${key}`)
    return handler(init)
  })
  vi.stubGlobal('fetch', fetchMock)
  return fetchMock
}

// The JSON body a fake handler received
export function bodyOf(init: RequestInit | undefined): unknown {
  return JSON.parse(String(init?.body))
}
```

### `src/lib/api.test.ts` (new)

```ts
import { afterEach, beforeEach, describe, expect, it, vi } from 'vitest'

import { json } from '../test/fakeApi'
import { api, ApiError, API_BASE_URL, setSessionExpiredHandler } from './api'
import { getTokens, saveTokens, type TokenResponse } from './tokens'

const ME = '/auth/me'
const REFRESH = `${API_BASE_URL}/auth/refresh`

function tokens(access: string, refresh: string): TokenResponse {
  return { access_token: access, refresh_token: refresh, token_type: 'bearer', expires_in: 1800 }
}

const INVALID_TOKEN = { error: { code: 'INVALID_TOKEN', message: 'The access token is invalid.' } }
const USER = { id: '1', email: 'ann@example.com', created_at: '2026-11-25T10:00:00Z' }

// The fake API: answers each call from a function of (url, init)
const fetchMock = vi.fn<typeof fetch>()

function authHeader(call: number): string | null {
  const init = fetchMock.mock.calls[call][1]
  return new Headers(init?.headers).get('Authorization')
}

function refreshCalls(): number {
  return fetchMock.mock.calls.filter(([url]) => url === REFRESH).length
}

// test/setup.ts clears localStorage and restores fetch around every test
beforeEach(() => {
  fetchMock.mockReset()
  vi.stubGlobal('fetch', fetchMock)
})

afterEach(() => {
  setSessionExpiredHandler(() => {})
})

describe('api', () => {
  it('sends the access token as a Bearer header', async () => {
    saveTokens(tokens('access-1', 'refresh-1'))
    fetchMock.mockResolvedValueOnce(json(200, USER))

    await expect(api(ME)).resolves.toEqual(USER)

    expect(fetchMock.mock.calls[0][0]).toBe(`${API_BASE_URL}${ME}`)
    expect(authHeader(0)).toBe('Bearer access-1')
  })

  it('sends no token when auth is false', async () => {
    saveTokens(tokens('access-1', 'refresh-1'))
    fetchMock.mockResolvedValueOnce(json(200, {}))

    await api('/auth/login', { method: 'POST', body: {}, auth: false })

    expect(authHeader(0)).toBeNull()
  })

  it('refreshes once on a 401 and retries with the new token', async () => {
    saveTokens(tokens('expired', 'refresh-1'))
    fetchMock
      .mockResolvedValueOnce(json(401, INVALID_TOKEN))
      .mockResolvedValueOnce(json(200, tokens('access-2', 'refresh-2')))
      .mockResolvedValueOnce(json(200, USER))

    await expect(api(ME)).resolves.toEqual(USER)

    expect(JSON.parse(String(fetchMock.mock.calls[1][1]?.body))).toEqual({
      refresh_token: 'refresh-1',
    })
    expect(authHeader(2)).toBe('Bearer access-2')
    expect(getTokens()).toEqual({ accessToken: 'access-2', refreshToken: 'refresh-2' })
  })

  it('ends the session when the refresh token is rejected too', async () => {
    const expired = vi.fn()
    setSessionExpiredHandler(expired)
    saveTokens(tokens('expired', 'expired-too'))
    fetchMock
      .mockResolvedValueOnce(json(401, INVALID_TOKEN))
      .mockResolvedValueOnce(json(401, INVALID_TOKEN))

    const error = await api(ME).catch((e: unknown) => e)

    expect(error).toBeInstanceOf(ApiError)
    expect(error).toMatchObject({ status: 401, code: 'INVALID_TOKEN' })
    expect(getTokens()).toBeNull()
    expect(expired).toHaveBeenCalledOnce()
  })

  it('shares one refresh between calls that get a 401 at the same time', async () => {
    saveTokens(tokens('expired', 'refresh-1'))
    fetchMock.mockImplementation(async (url, init) => {
      if (url === REFRESH) return json(200, tokens('access-2', 'refresh-2'))
      const ok = new Headers(init?.headers).get('Authorization') === 'Bearer access-2'
      return ok ? json(200, USER) : json(401, INVALID_TOKEN)
    })

    await Promise.all([api(ME), api(ME), api(ME)])

    expect(refreshCalls()).toBe(1)
  })

  it('does not refresh when a public call such as login gets a 401', async () => {
    const expired = vi.fn()
    setSessionExpiredHandler(expired)
    fetchMock.mockResolvedValueOnce(
      json(401, { error: { code: 'INVALID_CREDENTIALS', message: 'Wrong email or password.' } }),
    )

    const call = api('/auth/login', { method: 'POST', body: {}, auth: false })

    await expect(call).rejects.toMatchObject({ status: 401, code: 'INVALID_CREDENTIALS' })
    expect(refreshCalls()).toBe(0)
    expect(expired).not.toHaveBeenCalled()
  })

  it('turns the error envelope into an ApiError with field details', async () => {
    const details = [{ field: 'password', message: 'String should have at least 8 characters' }]
    fetchMock.mockResolvedValueOnce(
      json(422, {
        error: { code: 'VALIDATION_ERROR', message: 'The request is not valid.', details },
      }),
    )

    const call = api('/auth/register', { method: 'POST', body: {}, auth: false })

    await expect(call).rejects.toMatchObject({ status: 422, code: 'VALIDATION_ERROR', details })
  })

  it('reports a network failure as NETWORK_ERROR', async () => {
    fetchMock.mockRejectedValueOnce(new TypeError('Failed to fetch'))

    await expect(api(ME)).rejects.toMatchObject({ status: 0, code: 'NETWORK_ERROR' })
  })
})
```

### How the tests work

- **Acceptance criterion 4 is tested at two levels.** `api.test.ts` checks the client on its own: the header, refresh-and-retry, one shared refresh, and ending the session. `routing.test.tsx` checks the whole path through the real routes: an expired session really lands on `/login` with the tokens cleared.
- **No real network.** `fakeApi` replaces `fetch`, and any call without a handler throws `Unexpected API call: GET /auth/me`. A test can't quietly depend on a running API.
- **Tests find elements the way a user does**, by role, label and text, not by CSS class. The same tests keep passing when S0.4.2 restyles everything.

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| Browser console: *"blocked by CORS policy: No 'Access-Control-Allow-Origin' header"* | `CORSMiddleware` missing, or the page's origin isn't in `CORS_ORIGINS` | Step 1. The origin must match exactly: `http://127.0.0.1:5173` is not `http://localhost:5173`. Restart `api` after changing `.env`. |
| Login shows *"Could not reach the server. Is the API running?"* | The API is down, `VITE_API_BASE_URL` is wrong, or CORS refused | `docker compose ps`, then check `.env`, then the browser console |
| `Failed to resolve import "react-router-dom"` | Code copied from a v6 or v7 example | Import from `react-router`, and `RouterProvider` from `react-router/dom` |
| `Failed to resolve import "@tanstack/react-query"` in the container only | The old anonymous `node_modules` volume | `docker compose up -d --renew-anon-volumes frontend` |
| `npm warn EBADENGINE ... node: '>=22.22.0'` | An old cached `node:22-alpine`, or Node older than 22.22 locally | `docker compose build --pull frontend`; update Node locally |
| `tsc`: *"'test' does not exist in type 'UserConfigExport'"* | `defineConfig` imported from `vite` | Import it from `vitest/config` (Step 2) |
| Tests: `localStorage is not defined` or `document is not defined` | `test.environment` isn't `jsdom` | Step 2, `vite.config.ts` |
| Tests: `toBeInTheDocument is not a function` | The setup file isn't loaded | `setupFiles: ['./src/test/setup.ts']` |
