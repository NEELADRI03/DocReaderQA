# S0.3.1 — Registration with email and password

> **As a User, I want to register with email and password, so that my documents are private to me.**

**Acceptance criteria:**
1. **`POST /auth/register`** creates an account (full path: `/api/v1/auth/register`)
2. **The email is unique.** Registering the same email twice fails.
3. **The password is hashed** with argon2 or bcrypt. This guide uses argon2id.
4. **Validation errors use the standard error envelope**: `{"error": {"code": ..., "message": ...}}`

**Size:** M (1–2 days). Depends on S0.2.3, which must be merged first.

**Out of scope, don't build it yet:**
- **Logging in and tokens.** `POST /auth/login`, the JWT access token and the refresh token are S0.3.2. Registering returns the new user, not a token.
- **`get_current_user` and protected routes.** That's S0.3.3.
- **The register screen.** That's S0.4.2.
- **Email verification, password reset, and "is this password breached" checks.** These aren't in the backlog for v1.
- **Rate limiting.** The architecture lists a `RATE_LIMITED` code for that, and Phase 4 builds it.
- **An envelope for unhandled 500s.** A crash still returns Starlette's plain `Internal Server Error`. Every error the app raises on purpose uses the envelope.
- **A migration.** The `users` table from S0.2.2 already has `email UNIQUE` and `password_hash`.

## Architecture

A register request passes through three layers. Each one can refuse it, and every refusal leaves in the same envelope.

```
POST /api/v1/auth/register   {"email": "Ann@Example.com", "password": "..."}
         │
         ▼
┌──────────────────────────────────────┐   invalid   ┌──────────────────────────────┐
│ schemas/auth.py: RegisterRequest     │────────────▶│ api/errors.py                │
│ EmailStr, then lower-cased           │  Request-   │ VALIDATION_ERROR → 422       │
│ password: 8–128 characters           │  Validation-│ {"error": {code, message,    │
└────────┬─────────────────────────────┘  Error      │            details[]}}       │
         │ valid                                     │                              │
         ▼                                           │                              │
┌──────────────────────────────────────┐             │                              │
│ api/auth.py: register()              │             │                              │
│ 1. hash_password() in a thread ──────┼──▶ security.py: argon2id                   │
│ 2. INSERT INTO users                 │             │                              │
│ 3. commit                            │  duplicate  │ ApiError → EMAIL_TAKEN → 409 │
│    IntegrityError uq_users_email ────┼────────────▶│                              │
└────────┬─────────────────────────────┘             │ HTTPException (404, 405...)  │
         │ 201                                       │ → NOT_FOUND, ...             │
         ▼                                           └──────────────────────────────┘
{"id": "...", "email": "ann@example.com", "created_at": "..."}
```

Postgres's unique constraint decides whether an email is taken, not a `SELECT` before the `INSERT`. The reason is a race: two requests for the same email could both see "not taken" in a `SELECT`, but only one of them can pass the constraint.

**argon2id, not bcrypt.** This is a decision; record it in your decision log.
- OWASP's first choice for password storage is argon2id.
- It is memory-hard: each hash needs 64 MiB, which makes guessing on GPUs expensive.
- bcrypt ignores everything after 72 bytes of the password. argon2 has no such limit.
- `argon2-cffi` is the reference binding, ships wheels for Windows and Linux, and has type hints, so mypy strict is happy.

## Step 2 — `app/security.py`: hashing

```python
from argon2 import PasswordHasher
from argon2.exceptions import VerificationError

# argon2id with the library's defaults (RFC 9106 low-memory profile: 64 MiB, 3 passes)
_hasher = PasswordHasher()


def hash_password(password: str) -> str:
    # The result holds the algorithm, its parameters and a random salt: "$argon2id$v=19$m=..."
    return _hasher.hash(password)


def verify_password(password_hash: str, password: str) -> bool:
    try:
        return _hasher.verify(password_hash, password)
    except VerificationError:
        return False
```

### How the code works

- **One string holds everything.** A hash looks like `$argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>`, so the `password_hash` column needs nothing else: there's no separate salt column. If you raise the parameters later, old hashes still verify, because each hash carries its own.
- **A random salt per hash.** Two users with the same password get different hashes, so a leaked table doesn't show who shares a password. `test_same_password_hashes_differently_each_time` checks this.
- **It's slow on purpose.** One hash took about 78 ms on this machine. That's nothing for one sign-up, and expensive for someone guessing millions of passwords.
- **`verify_password` returns a bool instead of raising.** `VerificationError` is the base class for "wrong password" (`VerifyMismatchError`) and for a corrupted hash. Nothing in this story calls it outside the tests. Login in S0.3.2 does, and it only needs yes or no.
- **The argument order matches argon2's**: hash first, then password. Mixing them up gives `False`, not an error.

## Step 3 — `app/schemas/auth.py`: what goes in and out

Create `app/schemas/__init__.py` (empty) and `app/schemas/auth.py`:

```python
import uuid
from datetime import datetime
from typing import Annotated

from pydantic import AfterValidator, BaseModel, ConfigDict, EmailStr, Field

# Lower-cased, so Ann@Example.com and ann@example.com are one account
Email = Annotated[EmailStr, AfterValidator(str.lower)]

PASSWORD_MIN_LENGTH = 8
PASSWORD_MAX_LENGTH = 128


class RegisterRequest(BaseModel):
    email: Email
    # repr=False keeps the password out of reprs, so out of logs and tracebacks
    password: str = Field(
        min_length=PASSWORD_MIN_LENGTH, max_length=PASSWORD_MAX_LENGTH, repr=False
    )


class UserRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: uuid.UUID
    email: str
    created_at: datetime
```

### How the code works

- **`EmailStr`** checks the syntax only. It does no DNS lookup, so it works offline and in CI. It rejects special-use domains such as `.local`, `.test` and `localhost`, which is why the tests use `example.com`.
- **The whole address is lower-cased.** Strictly, the part before the `@` may be case-sensitive, but no mainstream mail provider treats it that way. Users do type `Ann@` one day and `ann@` the next. Since the stored email is always lower case, the plain `UNIQUE` constraint from S0.2.2 is enough, and login in S0.3.2 lower-cases the same way. Record this in your decision log too.
- **Password rules: 8 to 128 characters, nothing else.** That's the NIST SP 800-63B line: a minimum length, no "must contain a digit" rules. The upper bound keeps someone from sending a megabyte for argon2 to chew on.
- **`repr=False`, not `SecretStr`.** `SecretStr` also hides the value, but its length errors read "at least 8 *items*". With `repr=False`, `repr(body)` gives `RegisterRequest(email='ann@example.com')` and the messages stay normal: "String should have at least 8 characters".
- **`UserRead` is what the API returns**: never `password_hash`. `from_attributes=True` lets it read the SQLAlchemy `User` directly.

## Step 4 — `app/api/errors.py`: the error envelope

The architecture fixes one error shape for the whole API: `{"error": {"code": "DOCUMENT_NOT_READY", "message": "..."}}`. This step builds it once, so every later story raises `ApiError` and gets it for free.

```python
from http import HTTPStatus
from typing import Any

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import BaseModel
from starlette.exceptions import HTTPException as StarletteHTTPException


class FieldError(BaseModel):
    field: str
    message: str


class ErrorBody(BaseModel):
    code: str
    message: str
    details: list[FieldError] | None = None


class ErrorResponse(BaseModel):
    """The one error shape every endpoint returns: {"error": {"code": ..., "message": ...}}."""

    error: ErrorBody


class ApiError(Exception):
    """Raise this from a route to answer with the envelope and a stable code."""

    def __init__(self, status_code: int, code: str, message: str) -> None:
        super().__init__(message)
        self.status_code = status_code
        self.code = code
        self.message = message


def _envelope(status_code: int, body: ErrorBody) -> JSONResponse:
    content = ErrorResponse(error=body).model_dump(exclude_none=True)
    return JSONResponse(status_code=status_code, content=content)


def _field(error: dict[str, Any]) -> str:
    loc: tuple[Any, ...] = error["loc"]
    # Unparseable JSON has loc ("body", <character position>); the whole body is at fault
    if error["type"] == "json_invalid" or len(loc) == 1:
        return str(loc[0])
    # ("body", "email") -> "email", ("query", "limit") -> "limit", ("body", "items", 0) -> "items.0"
    return ".".join(str(part) for part in loc[1:])


async def _api_error(request: Request, exc: Exception) -> JSONResponse:
    assert isinstance(exc, ApiError)
    return _envelope(exc.status_code, ErrorBody(code=exc.code, message=exc.message))


async def _validation_error(request: Request, exc: Exception) -> JSONResponse:
    assert isinstance(exc, RequestValidationError)
    # Built from loc and msg only. FastAPI's default 422 also echoes "input", the password included.
    details = [FieldError(field=_field(err), message=err["msg"]) for err in exc.errors()]
    body = ErrorBody(code="VALIDATION_ERROR", message="The request is not valid.", details=details)
    return _envelope(422, body)


async def _http_error(request: Request, exc: Exception) -> JSONResponse:
    assert isinstance(exc, StarletteHTTPException)
    # 404 -> NOT_FOUND, 405 -> METHOD_NOT_ALLOWED, ...
    code = HTTPStatus(exc.status_code).name
    message = exc.detail if isinstance(exc.detail, str) else HTTPStatus(exc.status_code).phrase
    response = _envelope(exc.status_code, ErrorBody(code=code, message=message))
    if exc.headers:
        response.headers.update(exc.headers)
    return response


def register_error_handlers(app: FastAPI) -> None:
    app.add_exception_handler(ApiError, _api_error)
    app.add_exception_handler(RequestValidationError, _validation_error)
    app.add_exception_handler(StarletteHTTPException, _http_error)
```

### How the code works

- **Three handlers cover every error the app raises on purpose:**
  - `ApiError` is ours. It carries a stable `code` the frontend can switch on: `EMAIL_TAKEN` now, then `FILE_TOO_LARGE`, `NOT_A_PDF` and the rest in later stories.
  - `RequestValidationError` is FastAPI's: the body, query or path didn't match the schema.
  - `StarletteHTTPException` covers FastAPI's own 404 for an unknown route and 405 for a wrong method, plus any `HTTPException` a dependency raises. S0.3.3's 401 will come through here, and `exc.headers` keeps its `WWW-Authenticate` header.
- **`details` lists every bad field**: `[{"field": "password", "message": "String should have at least 8 characters"}]`. The register form in S0.4.2 can put each message under the right input. `exclude_none=True` leaves `details` out of errors that have none.
- **The password must not come back.** FastAPI's default 422 includes each field's `input`, so a too-short password is echoed in the response, and in any log that records responses. This handler builds the details from `loc` and `msg` only. `test_validation_error_does_not_echo_the_password` guards it.
- **`_field` drops the first part of `loc`**, which is `body`, `query` or `path`. The client knows it sent a body. Malformed JSON is the exception: its `loc` ends in a character position, so the field is reported as `body`.
- **Why `exc: Exception` and the `assert`.** Starlette types every handler as taking `Exception`. A handler declared with a narrower type would fail mypy strict. The `assert` narrows it, and it can't fail, because Starlette only calls each handler for its own class.
- **`HTTPStatus(...).name`** turns a status into a code (`404` → `NOT_FOUND`), so there is no table to keep up to date.

## Step 5 — `app/api/auth.py`: the endpoint

```python
from typing import Annotated

from fastapi import APIRouter, Depends, status
from sqlalchemy.exc import IntegrityError
from sqlalchemy.ext.asyncio import AsyncSession
from starlette.concurrency import run_in_threadpool

from app.api.errors import ApiError, ErrorResponse
from app.db.models import User
from app.db.session import get_session
from app.schemas.auth import RegisterRequest, UserRead
from app.security import hash_password

router = APIRouter(prefix="/auth", tags=["auth"])

Session = Annotated[AsyncSession, Depends(get_session)]


@router.post(
    "/register",
    status_code=status.HTTP_201_CREATED,
    responses={409: {"model": ErrorResponse}, 422: {"model": ErrorResponse}},
)
async def register(body: RegisterRequest, session: Session) -> UserRead:
    # argon2 takes ~50 ms of CPU on purpose. In a thread, so other requests keep running.
    password_hash = await run_in_threadpool(hash_password, body.password)

    user = User(email=body.email, password_hash=password_hash)
    session.add(user)

    try:
        await session.commit()
    except IntegrityError as exc:
        await session.rollback()
        # The unique constraint decides, so two requests racing for one email can't both win
        if "uq_users_email" in str(exc.orig):
            raise ApiError(
                status.HTTP_409_CONFLICT,
                "EMAIL_TAKEN",
                "An account with this email already exists.",
            ) from exc
        raise

    # created_at is filled in by Postgres; read it back
    await session.refresh(user)
    return UserRead.model_validate(user)
```

```python
register_error_handlers(app)
app.include_router(api_router)
```

### How the code works

- **`run_in_threadpool`.** Hashing is CPU work, roughly 50–80 ms. Called directly in an `async def`, it would block the event loop, so every other request, health checks included, would wait for it. In a thread, the loop keeps serving. argon2's C code releases the GIL, so this really does run in parallel.
- **Commit, and let Postgres say no.** As the Architecture section explains, a `SELECT` first would race. The `IntegrityError` text names the constraint, and `uq_users_email` is a fixed name thanks to the naming convention from S0.2.2. Any other integrity error is a bug, so it's re-raised, not turned into a 409.
- **`rollback()` after the failure.** A session whose flush failed can't be used again until it's rolled back. Nothing uses it afterwards here, but this way the request always leaves a clean session.
- **`refresh(user)`.** `created_at` has `server_default=now()`, so Postgres fills it in and the Python object doesn't have it. Reading it lazily isn't allowed in async SQLAlchemy (you'd get `MissingGreenlet`). `refresh` loads it explicitly.
- **201 with the user, no token.** Login (S0.3.2) gives out tokens. The frontend registers, then logs in.
- **409 reveals that an email has an account.** This is a known trade-off: someone can find out whether `x@y.com` is registered. Hiding that takes an email-confirmation flow ("check your inbox"), which v1 doesn't have. Rate limiting (Phase 4) is what slows down anyone abusing it. S0.3.2's login is different: there, the backlog says wrong credentials must not reveal which field was wrong. Record the trade-off in your decision log.
- **`responses=`** only documents the 409 and 422 shapes in `/docs`. It doesn't change behaviour.

```python
    email = new_email()
    first = await client.post(REGISTER, json={"email": email, "password": PASSWORD})

    # Differs only in case, so it is the same account
    second = await client.post(REGISTER, json={"email": email.upper(), "password": "another-pass"})

    assert first.status_code == 201
    assert second.status_code == 409
    assert second.json() == {
        "error": {"code": "EMAIL_TAKEN", "message": "An account with this email already exists."}
    }
```

### How the tests work

- **Two kinds of test in one file.**
  - The validation and envelope tests don't take the `sessions` fixture, so they run everywhere, CI included, without a database. Validation fails before the route body runs, so nothing connects. FastAPI does create a session for the request, but `AsyncSession` only connects on its first query.
  - The registration tests take `sessions`, which depends on `database_url`. Without `TEST_DATABASE_URL` they skip. CI sets it (S0.1.3), so they run on every PR.
- **`httpx2.ASGITransport` instead of `TestClient`.** `TestClient` runs the app on its own event loop in another thread. asyncpg connections belong to the loop that opened them, so an engine shared between the test and the app breaks. `ASGITransport` calls the app on the test's own loop, so the test and the route share one engine.
- **`app.dependency_overrides[get_session]`** points the route's `Session` at the test database. The app's own `engine` is never used, so `DATABASE_URL` can stay a dummy. `clear()` in teardown keeps the override from leaking into other tests.
- **Unique emails per test** (`new_email()`). The tests don't depend on each other's leftovers, and the module's `alembic_config` wipes the database at its start and end anyway.
- **`test_register_creates_...` reads the row back** to prove the acceptance criterion: what's stored is an argon2 hash that verifies, not the password.

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'argon2'` in the container | Image built before Step 1 | `docker compose up -d --build api worker` |
| `ImportError: email-validator is not installed` | `email-validator` missing from the venv or the image | `pip install -r requirements-dev.txt`, then rebuild |
| `relation "users" does not exist` | Migrations not applied | `docker compose exec api alembic upgrade head` |
| Every register returns 500 with `MissingGreenlet` | `session.refresh(user)` left out | Keep the `refresh` before `model_validate` |
| A duplicate email returns 500, not 409 | The constraint isn't named `uq_users_email` (migration made without the naming convention) | `\d users` in `psql`; the S0.2.2 migration must create `uq_users_email` |
| 422 body is `{"detail": [...]}`, not `{"error": ...}` | `register_error_handlers(app)` not called | Add it in `main.py` |
| `test@example.local` rejected | `EmailStr` refuses special-use domains | Use a real domain; tests use `example.com` |
| DB tests: `got Future attached to a different loop` | Test uses `TestClient` with a shared engine | Use the `client` fixture (`ASGITransport`) |
| `fixture 'database_url' not found` | Fixtures not moved into `conftest.py` | Step 6 |
| Registration tests show as skipped | `TEST_DATABASE_URL` not set in this terminal | See the README's Code quality section |
| mypy: incompatible type for `add_exception_handler` | Handler declared as `exc: ApiError` | Declare `exc: Exception` and `assert isinstance` |
