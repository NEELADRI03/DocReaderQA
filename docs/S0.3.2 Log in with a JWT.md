# S0.3.2 — Log in with a JWT

> **As a User, I want to log in, so that I get access to my workspace.**

**Acceptance criteria:**
1. **`POST /auth/login` returns a JWT access token**, plus a refresh token (full path: `/api/v1/auth/login`).
2. **Wrong credentials return 401 without revealing which field was wrong.** An unknown email and a wrong password get the same answer.

**Size:** S (half a day to a day). Depends on S0.3.1, which must be merged first.

**Out of scope, don't build it yet:**
- **`get_current_user` and protected routes.** That's S0.3.3. This story builds `decode_token()`, which S0.3.3 calls, but no route checks a token yet.
- **The login screen, storing the token, and logout.** That's S0.4.1 and S0.4.2. Logout in v1 just means the frontend throws its tokens away.
- **Revoking tokens.** Refresh tokens are stateless JWTs here: nothing is stored in the database, so one stays valid until it expires (see the decision log at the end of Step 5).
- **Rate limiting and lockout after failed logins.** The architecture puts rate limits in Phase 4.
- **A migration.** Nothing new is stored.

## Architecture

```
POST /api/v1/auth/login   {"email": "Ann@Example.com", "password": "..."}
         │
         ▼
┌──────────────────────────────────────┐  invalid   ┌───────────────────────────────┐
│ schemas/auth.py: LoginRequest        │───────────▶│ api/errors.py                 │
│ EmailStr, lower-cased                │            │ VALIDATION_ERROR → 422        │
└────────┬─────────────────────────────┘            │                               │
         ▼                                          │                               │
┌──────────────────────────────────────┐            │                               │
│ api/auth.py: login()                 │            │                               │
│ 1. SELECT user by email              │            │                               │
│ 2. verify_password() in a thread     │            │                               │
│    (DUMMY_PASSWORD_HASH if no user)  │  no match  │ ApiError                      │
│ 3. user and password both OK? ───────┼───────────▶│ INVALID_CREDENTIALS → 401     │
└────────┬─────────────────────────────┘            │ + WWW-Authenticate: Bearer    │
         │ yes                                      └───────────────────────────────┘
         ▼
┌──────────────────────────────────────┐
│ tokens.py: create_token()            │   HS256, signed with JWT_SECRET
│ access:  sub, type, iat, exp (30 m)  │
│ refresh: sub, type, iat, exp (7 d)   │
└────────┬─────────────────────────────┘
         ▼
{"access_token": "...", "refresh_token": "...", "token_type": "bearer", "expires_in": 1800}


POST /api/v1/auth/refresh   {"refresh_token": "..."}
   decode_token(token, "refresh") ─ bad, expired, or an access token ─▶ INVALID_TOKEN → 401
   user still exists? ─ no ─▶ INVALID_TOKEN → 401
   yes ─▶ a new access token and a new refresh token
```

**Two tokens, one secret.** The access token goes on every API call (S0.3.3 checks it). It lives 30 minutes, so a stolen one stops working soon. The refresh token is only ever sent to `/auth/refresh`, to get a new pair without asking for the password again. It lives 7 days. A `type` claim tells them apart, so a refresh token can never be used as an access token. Both lifetimes come from `ACCESS_TOKEN_MINUTES` and `REFRESH_TOKEN_DAYS`, which have been in `config.py` since S0.2.1.

The acceptance criterion only asks login to *return* a refresh token. This guide also adds `POST /auth/refresh`, because a refresh token with nothing that accepts it is dead weight, and the endpoint is about 15 lines.

**PyJWT, not python-jose.** Record this in your decision log.
- PyJWT is maintained, ships type hints (`py.typed`), so mypy strict is happy, and has no dependencies for HS256.
- python-jose, which older FastAPI tutorials use, had long gaps between releases and open security issues. FastAPI's own docs switched to PyJWT.
- HS256 (one shared secret) is enough because the API is the only thing that issues and checks tokens. RS256 (a key pair) is for when other services must check tokens without being able to issue them.

## Step 3 — `app/tokens.py`: signing and checking

```python
import uuid
from datetime import UTC, datetime, timedelta
from typing import Literal

import jwt

from app.config import get_settings

ALGORITHM = "HS256"

TokenType = Literal["access", "refresh"]


class InvalidTokenError(Exception):
    """The token is malformed, tampered with, expired, or of the wrong type."""


def token_lifetime(token_type: TokenType) -> timedelta:
    settings = get_settings()
    if token_type == "access":
        return timedelta(minutes=settings.access_token_minutes)
    return timedelta(days=settings.refresh_token_days)


def create_token(user_id: uuid.UUID, token_type: TokenType) -> str:
    now = datetime.now(UTC)
    claims = {
        "sub": str(user_id),
        "type": token_type,
        "iat": now,
        "exp": now + token_lifetime(token_type),
        # Unique per token, so a later story can revoke one refresh token by its ID
        "jti": uuid.uuid4().hex,
    }
    secret = get_settings().jwt_secret.get_secret_value()
    return jwt.encode(claims, secret, algorithm=ALGORITHM)


def decode_token(token: str, token_type: TokenType) -> uuid.UUID:
    """Return the user ID in a valid token of the given type, or raise InvalidTokenError."""
    secret = get_settings().jwt_secret.get_secret_value()
    try:
        # Pinning algorithms stops a token from choosing its own, such as "none"
        claims = jwt.decode(
            token, secret, algorithms=[ALGORITHM], options={"require": ["exp", "sub", "type"]}
        )
        # Without this, a refresh token, which lives for days, would work as an access token
        if claims["type"] != token_type:
            raise InvalidTokenError(f"expected a {token_type} token")
        return uuid.UUID(claims["sub"])
    except (jwt.InvalidTokenError, ValueError) as exc:
        raise InvalidTokenError(str(exc)) from exc
```

### How the code works

- **Its own module, not `security.py`.** `security.py` is pure hashing with no config. Tokens need `JWT_SECRET` and the lifetimes. S0.3.3's `get_current_user` will import `decode_token` from here.
- **The claims.** `sub` (subject) is the user's ID, as a string because the JWT spec says so. `iat` and `exp` are issued-at and expiry; PyJWT turns the `datetime`s into Unix seconds and checks `exp` on decode. `jti` makes every token unique, even two issued for the same user in the same second.
- **The payload is signed, not encrypted.** Anyone holding a token can read its claims (paste one into jwt.io). That's why it holds only the user ID: no email, nothing private.
- **`algorithms=[ALGORITHM]` is the important line.** A JWT names its own algorithm in its header. If the server trusted that, an attacker could send `"alg": "none"` with no signature. Pinning the list rejects it; `test_unsigned_token_is_rejected` proves it.
- **`require`** makes a token without `exp`, `sub` or `type` invalid, instead of a token that never expires.
- **One exception type out.** PyJWT has a dozen (`ExpiredSignatureError`, `InvalidSignatureError`, `DecodeError`...), all subclasses of `jwt.InvalidTokenError`. `ValueError` covers a `sub` that isn't a UUID. Callers only need "valid or not", so they all become our `InvalidTokenError`, with the reason kept in the message for logs.
- **The lifetime is read on every call**, not at import. `get_settings()` is cached, so this costs nothing, and tests can change the settings.

## Step 4 — Schemas, the dummy hash, and headers on `ApiError`

### `app/schemas/auth.py`

Add `Literal` to the `typing` import:

```python
from typing import Annotated, Literal
```

and these three models at the end:

```python
class LoginRequest(BaseModel):
    email: Email
    # No minimum: length rules are for choosing a password, and a wrong one just doesn't match
    password: str = Field(max_length=PASSWORD_MAX_LENGTH, repr=False)


class RefreshRequest(BaseModel):
    refresh_token: str


class TokenResponse(BaseModel):
    access_token: str
    refresh_token: str
    token_type: Literal["bearer"] = "bearer"
    # Seconds until the access token expires
    expires_in: int
```

- **`email: Email`** reuses S0.3.1's lower-casing, so `Ann@Example.com` logs in to the account registered as `ann@example.com`.
- **No `min_length` on the password.** If the minimum is ever raised, users with older, shorter passwords must still be able to log in. The maximum stays, so nobody can make argon2 hash a megabyte.
- **A malformed email still gets a 422**, not a 401. That reveals nothing about any account: anybody can see `ann` isn't an email address.
- **JSON, not a form.** FastAPI tutorials often use `OAuth2PasswordRequestForm` (form fields `username` and `password`). JSON matches `/auth/register` and the React client. The cost: the **Authorize** button in `/docs` can't log in for you. You paste a token into it instead (S0.3.3).
- **`token_type` and `expires_in`** follow the OAuth 2 token response (RFC 6749 §5.1). The frontend can use `expires_in` to refresh before the access token runs out.

### `app/security.py`

Add `import secrets` at the top, and this at the end:

```python
# Login checks against this when the email is unknown. The check then takes as long as a
# real one, so response time doesn't tell an attacker which emails are registered.
DUMMY_PASSWORD_HASH = hash_password(secrets.token_urlsafe(32))
```

It's hashed once, at import (about 80 ms). The password is random and thrown away, so nobody can match it.

### `app/api/errors.py`

A 401 must carry a `WWW-Authenticate` header (RFC 9110 §15.5.2). `ApiError` couldn't carry headers until now. Change the class and `_envelope`, and pass the headers on in `_api_error`:

```python
class ApiError(Exception):
    """Raise this from a route to answer with the envelope and a stable code."""

    def __init__(
        self, status_code: int, code: str, message: str, headers: dict[str, str] | None = None
    ) -> None:
        super().__init__(message)
        self.status_code = status_code
        self.code = code
        self.message = message
        self.headers = headers


def _envelope(
    status_code: int, body: ErrorBody, headers: dict[str, str] | None = None
) -> JSONResponse:
    content = ErrorResponse(error=body).model_dump(exclude_none=True)
    return JSONResponse(status_code=status_code, content=content, headers=headers)
```

```python
async def _api_error(request: Request, exc: Exception) -> JSONResponse:
    assert isinstance(exc, ApiError)
    body = ErrorBody(code=exc.code, message=exc.message)
    return _envelope(exc.status_code, body, exc.headers)
```

The other handlers don't change. `headers` defaults to `None`, so the S0.3.1 `EMAIL_TAKEN` call keeps working as it is.

## Step 5 — `app/api/auth.py`: login and refresh

The whole file. `register()` is unchanged from S0.3.1; the imports, `BEARER`, `_issue_tokens`, `login()` and `refresh()` are new.

```python
import uuid
from typing import Annotated

from fastapi import APIRouter, Depends, status
from sqlalchemy import select
from sqlalchemy.exc import IntegrityError
from sqlalchemy.ext.asyncio import AsyncSession
from starlette.concurrency import run_in_threadpool

from app.api.errors import ApiError, ErrorResponse
from app.db.models import User
from app.db.session import get_session
from app.schemas.auth import (
    LoginRequest,
    RefreshRequest,
    RegisterRequest,
    TokenResponse,
    UserRead,
)
from app.security import DUMMY_PASSWORD_HASH, hash_password, verify_password
from app.tokens import InvalidTokenError, create_token, decode_token, token_lifetime

router = APIRouter(prefix="/auth", tags=["auth"])

Session = Annotated[AsyncSession, Depends(get_session)]

# RFC 9110: a 401 response must say which scheme the client should authenticate with
BEARER = {"WWW-Authenticate": "Bearer"}


@router.post(
    "/register",
    status_code=status.HTTP_201_CREATED,
    responses={409: {"model": ErrorResponse}, 422: {"model": ErrorResponse}},
)
async def register(body: RegisterRequest, session: Session) -> UserRead:
    password_hash = await run_in_threadpool(hash_password, body.password)

    user = User(email=body.email, password_hash=password_hash)
    session.add(user)
    try:
        await session.commit()
    except IntegrityError as exc:
        await session.rollback()

        if "uq_users_email" in str(exc.orig):
            raise ApiError(
                status.HTTP_409_CONFLICT,
                "EMAIL_TAKEN",
                "An account with this email already exists.",
            ) from exc
        raise

    await session.refresh(user)
    return UserRead.model_validate(user)


def _issue_tokens(user_id: uuid.UUID) -> TokenResponse:
    return TokenResponse(
        access_token=create_token(user_id, "access"),
        refresh_token=create_token(user_id, "refresh"),
        expires_in=int(token_lifetime("access").total_seconds()),
    )


@router.post(
    "/login",
    responses={401: {"model": ErrorResponse}, 422: {"model": ErrorResponse}},
)
async def login(body: LoginRequest, session: Session) -> TokenResponse:
    user = await session.scalar(select(User).where(User.email == body.email))

    # Always run one argon2 check, even with no user, so timing doesn't reveal the email.
    # A user without a password hash (not possible yet) can't log in with a password.
    password_hash = user.password_hash if user and user.password_hash else DUMMY_PASSWORD_HASH
    password_ok = await run_in_threadpool(verify_password, password_hash, body.password)

    if user is None or user.password_hash is None or not password_ok:
        # One answer for unknown email and wrong password, so neither field is singled out
        raise ApiError(
            status.HTTP_401_UNAUTHORIZED,
            "INVALID_CREDENTIALS",
            "The email or password is incorrect.",
            headers=BEARER,
        )

    return _issue_tokens(user.id)


@router.post(
    "/refresh",
    responses={401: {"model": ErrorResponse}, 422: {"model": ErrorResponse}},
)
async def refresh(body: RefreshRequest, session: Session) -> TokenResponse:
    invalid = ApiError(
        status.HTTP_401_UNAUTHORIZED,
        "INVALID_TOKEN",
        "The refresh token is invalid or has expired.",
        headers=BEARER,
    )
    try:
        user_id = decode_token(body.refresh_token, "refresh")
    except InvalidTokenError as exc:
        raise invalid from exc

    # The account may have been deleted since the token was issued
    if await session.get(User, user_id) is None:
        raise invalid

    return _issue_tokens(user_id)
```

### How the code works

- **"Without revealing which field was wrong" has two halves.**
  - *The response:* an unknown email and a wrong password raise the same `ApiError`, with the same code, message and header. `test_wrong_password_and_unknown_email_look_the_same` compares them.
  - *The timing:* without the dummy hash, an unknown email would return after one quick `SELECT`, and a wrong password only after argon2's ~60 ms, because only the second runs it. An attacker could time responses to find out which emails have accounts. With `DUMMY_PASSWORD_HASH`, both paths run one argon2 check. On this machine, six alternating tries gave 54–67 ms for both.
- **`user.password_hash is None` is checked again** after verifying. The column is nullable (S0.2.2 left room for sign-in without a password, such as SSO). Such a user is checked against the dummy hash for timing, and then refused even if the check somehow matched.
- **`run_in_threadpool`** for the same reason as in register: argon2 takes about 80 ms of CPU, and the event loop must stay free for other requests meanwhile.
- **200, not 201.** Login creates no resource, so FastAPI's default status is right.
- **The 401 path also sends `WWW-Authenticate: Bearer`.** HTTP requires it on every 401. Browsers ignore it for Bearer (they show a login dialog only for `Basic`), so it's harmless.
- **Refresh checks that the user still exists.** A token is valid on its own, without the database. Without this one lookup, a deleted account could keep getting fresh tokens for up to 7 days.
- **Refresh returns a new refresh token too** (rotation), so an active user never hits the 7-day limit. Because nothing is stored, the old refresh token also stays valid until it expires. That's the decision below.
- **Both refresh failures give the same `INVALID_TOKEN`**: a client can't tell "expired" from "user deleted", and doesn't need to: both mean "log in again".

**Record these in your decision log:**
- **Access and refresh tokens are stateless JWTs (HS256), with nothing stored.** It's simpler and needs no table. The cost: a token can't be revoked before it expires, and logout only deletes the tokens in the browser. If revocation is needed later, store each refresh token's `jti` in a table and check it in `refresh()`. The `jti` claim is already there for that.
- **The tokens go in the JSON response body.** Where the frontend keeps them (memory, `localStorage`, or an httpOnly cookie set by the API) is S0.4.1's decision.
- **Login returns 401 `INVALID_CREDENTIALS` for both an unknown email and a wrong password**, and takes the same time for both. Note that `/auth/register` still reveals whether an email is registered (409 `EMAIL_TAKEN`, recorded in S0.3.1), so this protects against timing guesses on login, not against someone determined to probe emails.

### `tests/test_tokens.py` (new)

```python
import uuid
from datetime import UTC, datetime, timedelta

import jwt
import pytest

from app.config import get_settings
from app.tokens import ALGORITHM, InvalidTokenError, create_token, decode_token


def _sign(claims: dict[str, object], secret: str | None = None) -> str:
    key = secret or get_settings().jwt_secret.get_secret_value()
    return jwt.encode(claims, key, algorithm=ALGORITHM)


def test_access_token_round_trip() -> None:
    user_id = uuid.uuid4()

    assert decode_token(create_token(user_id, "access"), "access") == user_id


def test_refresh_token_is_not_an_access_token() -> None:
    token = create_token(uuid.uuid4(), "refresh")

    with pytest.raises(InvalidTokenError):
        decode_token(token, "access")


def test_tokens_are_unique() -> None:
    # Same user, same second: the jti claim still makes them differ
    user_id = uuid.uuid4()

    assert create_token(user_id, "refresh") != create_token(user_id, "refresh")


def test_expired_token_is_rejected() -> None:
    past = datetime.now(UTC) - timedelta(minutes=1)
    token = _sign({"sub": str(uuid.uuid4()), "type": "access", "exp": past})

    with pytest.raises(InvalidTokenError):
        decode_token(token, "access")


@pytest.mark.parametrize(
    "token",
    [
        "not-a-jwt",
        # Signed with another key
        _sign(
            {"sub": str(uuid.uuid4()), "type": "access", "exp": datetime.now(UTC) + timedelta(1)},
            secret="some-other-secret-that-is-32-chars-or-more",
        ),
        # No expiry
        _sign({"sub": str(uuid.uuid4()), "type": "access"}),
        # Subject is not a user ID
        _sign({"sub": "admin", "type": "access", "exp": datetime.now(UTC) + timedelta(1)}),
    ],
    ids=["garbage", "wrong-key", "no-exp", "bad-sub"],
)
def test_invalid_tokens_are_rejected(token: str) -> None:
    with pytest.raises(InvalidTokenError):
        decode_token(token, "access")


def test_unsigned_token_is_rejected() -> None:
    # alg "none" has no signature at all; anyone could write one
    claims = {"sub": str(uuid.uuid4()), "type": "access", "exp": datetime.now(UTC) + timedelta(1)}
    token = jwt.encode(claims, None, algorithm="none")

    with pytest.raises(InvalidTokenError):
        decode_token(token, "access")
```

```python
    email, _ = await register_user(client)

    wrong_password = await client.post(LOGIN, json={"email": email, "password": "wrong-pass"})
    unknown_email = await client.post(LOGIN, json={"email": new_email(), "password": PASSWORD})

    for response in (wrong_password, unknown_email):
        assert response.status_code == 401
        assert response.json() == INVALID_CREDENTIALS
        assert response.headers["www-authenticate"] == "Bearer"


async def test_login_without_password_is_a_validation_error(client: httpx2.AsyncClient) -> None:
    response = await client.post(LOGIN, json={"email": "ann@example.com"})

    assert response.status_code == 422
    assert [detail["field"] for detail in response.json()["error"]["details"]] == ["password"]


async def test_refresh_returns_new_tokens(
    client: httpx2.AsyncClient, sessions: async_sessionmaker[AsyncSession]
) -> None:
    email, user_id = await register_user(client)
    login = await client.post(LOGIN, json={"email": email, "password": PASSWORD})

    response = await client.post(REFRESH, json={"refresh_token": login.json()["refresh_token"]})

    assert response.status_code == 200
    body = response.json()
    assert decode_token(body["access_token"], "access") == user_id
    assert body["refresh_token"] != login.json()["refresh_token"]


async def test_access_token_cannot_be_used_to_refresh(
    client: httpx2.AsyncClient, sessions: async_sessionmaker[AsyncSession]
) -> None:
    email, _ = await register_user(client)
    login = await client.post(LOGIN, json={"email": email, "password": PASSWORD})

    response = await client.post(REFRESH, json={"refresh_token": login.json()["access_token"]})

    assert response.status_code == 401
    assert response.json()["error"]["code"] == "INVALID_TOKEN"


async def test_refresh_for_a_deleted_user_is_rejected(
    client: httpx2.AsyncClient, sessions: async_sessionmaker[AsyncSession]
) -> None:
    _, user_id = await register_user(client)
    token = create_token(user_id, "refresh")
    async with sessions() as session:
        await session.execute(delete(User).where(User.id == user_id))
        await session.commit()

    response = await client.post(REFRESH, json={"refresh_token": token})

    assert response.status_code == 401
    assert response.json()["error"]["code"] == "INVALID_TOKEN"
```

### How the tests work

- **`test_tokens.py` needs no database.** It runs everywhere, CI included, and covers each way a token can be bad: garbage, wrong key, expired, no `exp`, a `sub` that isn't a UUID, `alg: none`, and the wrong type.
- **`_sign` builds tokens by hand** with PyJWT, because `create_token` can't make a broken one. The parametrized tokens are built when the module is imported, which works because `conftest.py` sets `JWT_SECRET` first.
- **`timedelta(1)` is one day**: the first positional argument of `timedelta` is days.
- **The login tests register through the API** (`register_user`), so they exercise the real register-then-login flow, with a fresh email each time.
- **`test_login_without_password_...` takes no `sessions`**, so it runs without a database: validation fails before the route touches one.
- **`test_refresh_for_a_deleted_user_...`** deletes the row directly through `sessions`, then shows a token that is still cryptographically valid is refused.
- **The timing isn't tested.** A timing assertion would be flaky on a busy CI runner. It's checked by hand in Step 8 instead.

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError: No module named 'jwt'` in the container | Image built before Step 1 | `docker compose up -d --build api worker` |
| `ImportError: cannot import name 'InvalidTokenError'` from `jwt`, or odd `jwt` errors | The unrelated `jwt` package is installed instead of `pyjwt` (both import as `jwt`) | `pip uninstall jwt`, then `pip install -r requirements-dev.txt` |
| API won't start: `jwt_secret ... at least 32 items` | `.env` still has a short `JWT_SECRET` | Generate one (Step 2) and `docker compose up -d api` |
| `InsecureKeyLengthWarning` in test output | `conftest.py` still sets `test-secret`, or the terminal has a short `JWT_SECRET` set | Step 2's conftest change; `Remove-Item Env:JWT_SECRET` |
| Every login returns 401, even with the right password | The row was inserted by hand (an email with capitals, or no argon2 hash) instead of through `/auth/register` | Check `SELECT email, left(password_hash, 10) FROM users`; register again through the API |
| Login works but every refresh returns 401 | Sending the access token instead of the refresh token, or the secret changed since login | Use `refresh_token`; changing `JWT_SECRET` invalidates every token, which is expected |
| All tokens stop working after a restart | `JWT_SECRET` is generated at startup somewhere instead of fixed in `.env` | Keep one fixed secret per environment |
| `ExpiredSignatureError` right after login in Docker | The container's clock is off from the host | Restart Docker Desktop (WSL clock drift after sleep) |
| 401 body is `{"detail": ...}`, not `{"error": ...}` | Raised `HTTPException` with a `dict` detail instead of `ApiError` | Raise `ApiError` |
| 401 has no `WWW-Authenticate` header | Step 4's `headers` change to `ApiError` and `_envelope` missing | Step 4 |
| mypy: `Module "jwt" has no attribute ...` | Old PyJWT (< 2.0) without type hints | `pip install -U "pyjwt>=2.10"` |
