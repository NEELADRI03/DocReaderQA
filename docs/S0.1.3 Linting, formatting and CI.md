# S0.1.3 — Linting, formatting and CI

> **As a Dev, I want linting, formatting and CI, so that code quality is enforced from day one.**

**Acceptance criteria (issue #4):**
1. Backend: **ruff** (lint + format) and **mypy**
2. Frontend: **ESLint**, **Prettier** and **tsc**
3. **pre-commit** hooks run the same checks
4. **GitHub Actions** runs lint, type checks and tests on every PR

The issue says `tsc --noEmit`. This project uses `tsc -b` instead: the root `tsconfig.json` only holds project references, so plain `tsc --noEmit` would check nothing. The referenced configs already set `noEmit`.

**Size:** S (up to half a day). Depends on S0.1.1. It does not need Ollama.

**Out of scope, don't build it yet:**
- Real tests. You add **one** smoke test (`/api/v1/health`) so CI has something to run. Each later story brings its own tests.
- Frontend unit tests (Vitest). The frontend has no logic yet, so CI checks it with lint, format, type check and build.

CI runs on pull requests, so you need a `main` branch on GitHub to open one against. The local repo has no commits yet, and `NEELADRI03/DocReaderQA` on GitHub is empty.

**a)** Rename the branch to `main`:

```powershell

```

**b)** Create `.gitattributes` in the repo root **before the first commit**, so every file goes in with LF line endings. Docker, CI (Linux) and Prettier all expect LF. On Windows, files are often saved with CRLF.

```gitattributes
# Store text files with LF so Linux containers, CI and Prettier all agree
* text=auto eol=lf

*.ps1 text eol=crlf
*.pdf binary
*.png binary
```

**c)** Commit S0.1.1 and S0.1.2 and push. Check `git status` first, and leave out anything you don't want public (the repo is **public**). `.env` is already ignored.

## Step 1 — Backend: ruff, mypy and a smoke test

**a)** Create `docqa-backend/requirements-dev.txt`. Dev tools stay out of `requirements.txt`, so the Docker image doesn't carry them.

```text
-r requirements.txt

ruff==0.17.2
mypy==2.4.0
pytest==9.1.1
# Starlette's TestClient needs httpx2 (plain httpx is deprecated for it)
httpx2>=2.16
pre-commit==4.7.0
```

**b)** Create `docqa-backend/pyproject.toml` with the tool settings:

```toml
# Tool settings only. Dependencies stay in requirements*.txt
[tool.ruff]
target-version = "py312"
line-length = 100

[tool.ruff.lint]
# E/W pycodestyle, F pyflakes, I import order, B bugbear, UP pyupgrade, SIM simplify
select = ["E", "W", "F", "I", "B", "UP", "SIM"]

[tool.mypy]
python_version = "3.12"
strict = true

[tool.pytest.ini_options]
testpaths = ["tests"]
```

`strict = true` is the "from day one" part. Strict mode is easy to keep on a tiny codebase, and painful to turn on later.

**c)** Create the smoke test. `docqa-backend/tests/__init__.py` is an empty file. Then `docqa-backend/tests/test_health.py`:

```python
from fastapi.testclient import TestClient

from app.main import app

client = TestClient(app)


def test_health_returns_ok() -> None:
    response = client.get("/api/v1/health")

    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

**d)** Install the tools into the existing virtual environment:

```powershell
cd docqa-backend
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

If `Activate.ps1` is blocked ("running scripts is disabled"), run this once and try again:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

**e)** Run the checks. The current code **will fail** at first:

```powershell
ruff check .            # 4 errors: import order, missing final newline
ruff format --check .   # 2 files would be reformatted
mypy app tests          # tasks.py: Missing type arguments for generic type "dict"
pytest                  # 1 passed
```

**f)** Fix it. Ruff fixes its own findings:

```powershell
ruff check --fix .
ruff format .
```

mypy needs one manual change. In `app/workers/tasks.py`, arq passes `ctx` as a `dict[str, Any]`:

```python
import os
from typing import Any

from arq.connections import RedisSettings


async def ping(ctx: dict[str, Any]) -> str:
    return "pong"
```

**g)** Run everything again. All four must pass:

```powershell
ruff check .            # All checks passed!
ruff format --check .   # 6 files already formatted
mypy app tests          # Success: no issues found in 6 source files
pytest                  # 1 passed
cd ..
```

## Step 2 — Frontend: swap oxlint for ESLint + Prettier

The Vite template (create-vite 9) ships **oxlint**. The backlog asks for **ESLint**, so replace it.

**a)** Remove oxlint and install ESLint, Prettier and the plugins:

```powershell
cd docqa-frontend
Remove-Item .oxlintrc.json
npm uninstall oxlint
npm install --save-dev eslint@10 @eslint/js@10 typescript-eslint@8 eslint-plugin-react-hooks@7 eslint-plugin-react-refresh@0.5 globals@17 prettier@3 eslint-config-prettier@10
```

(`typescript-eslint` 8.72 supports TypeScript up to 6.0.x, which is what the project uses.)

**b)** Create `docqa-frontend/eslint.config.js`:

```js
import js from '@eslint/js'
import prettier from 'eslint-config-prettier'
import reactHooks from 'eslint-plugin-react-hooks'
import reactRefresh from 'eslint-plugin-react-refresh'
import { defineConfig, globalIgnores } from 'eslint/config'
import globals from 'globals'
import tseslint from 'typescript-eslint'

export default defineConfig([
  globalIgnores(['dist']),
  {
    files: ['**/*.{ts,tsx}'],
    extends: [
      js.configs.recommended,
      tseslint.configs.recommended,
      reactHooks.configs.flat.recommended,
      reactRefresh.configs.vite,
    ],
    languageOptions: {
      ecmaVersion: 2022,
      globals: globals.browser,
    },
  },
  // Last, so Prettier owns formatting and ESLint only checks code quality
  prettier,
])
```

**c)** Create `docqa-frontend/.prettierrc.json`. These options match the style the template already uses:

```json
{
  "semi": false,
  "singleQuote": true,
  "printWidth": 100
}
```

and `docqa-frontend/.prettierignore`:

```text
dist
node_modules
package-lock.json
```

**d)** Set the npm scripts:

```powershell
npm pkg set scripts.lint="eslint ." scripts.format="prettier --write ." scripts.format:check="prettier --check ." scripts.typecheck="tsc -b"
```

**e)** Run the checks:

```powershell
npm run lint            # no output = pass
npm run format:check    # flags 4 template files: App.css, App.tsx, index.css, tsconfig.json
npm run typecheck       # no output = pass
```

**f)** Format once, then check again:

```powershell
npm run format
npm run format:check    # All matched files use Prettier code style!
npm run build           # still builds
cd ..
```

## Step 3 — pre-commit hooks

`pre-commit` runs the checks on every `git commit`, before bad code reaches a PR. It was installed with the backend dev tools in Step 1.

**a)** Create `.pre-commit-config.yaml` in the repo root:

```yaml
# Runs on every `git commit`. Run on all files: pre-commit run --all-files
# Some PDFs look like text to the whitespace hooks, which would corrupt them
exclude: \.pdf$
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v6.0.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-merge-conflict
      - id: check-added-large-files
        args: [--maxkb=1024]

  # Backend: ruff finds docqa-backend/pyproject.toml on its own
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.17.2
    hooks:
      - id: ruff-check
        args: [--fix]
        files: ^docqa-backend/
      - id: ruff-format
        files: ^docqa-backend/

  - repo: https://github.com/pre-commit/mirrors-mypy
    rev: v2.4.0
    hooks:
      - id: mypy
        files: ^docqa-backend/
        # Check the whole backend, not just the changed files, so imports resolve
        pass_filenames: false
        args: [--config-file=docqa-backend/pyproject.toml, docqa-backend/app, docqa-backend/tests]
        # mypy runs in its own environment, so it needs the packages it type-checks against
        additional_dependencies: [fastapi, arq, pytest, httpx2]

  # Frontend: uses the tools installed in docqa-frontend/node_modules
  - repo: local
    hooks:
      - id: frontend-eslint
        name: eslint (frontend)
        entry: npm --prefix docqa-frontend run lint
        language: system
        files: ^docqa-frontend/.*\.(ts|tsx|js)$
        pass_filenames: false
      - id: frontend-prettier
        name: prettier (frontend)
        entry: npm --prefix docqa-frontend run format:check
        language: system
        files: ^docqa-frontend/
        pass_filenames: false
      - id: frontend-tsc
        name: tsc (frontend)
        entry: npm --prefix docqa-frontend run typecheck
        language: system
        files: ^docqa-frontend/.*\.(ts|tsx)$|^docqa-frontend/tsconfig.*\.json$
        pass_filenames: false
```

The `exclude: \.pdf$` line matters. Without it, `trailing-whitespace` edits `README.pdf`, which it wrongly treats as text, and can corrupt it.

`--maxkb=1024` is there because the architecture PDF in `docs/` is 610 KB, over the 500 KB default.

> **Keep `additional_dependencies` in sync.** When a later story adds a backend package that the code imports (for example SQLAlchemy in S0.2.x), add it here too, or the mypy hook will report missing imports.

**b)** Add the tool caches to the root `.gitignore`, under `# Python`:

```gitignore
.mypy_cache/
.ruff_cache/
.pytest_cache/
```

**c)** Install the git hook and run every hook on every file once. The venv from Step 1 must be active:

```powershell
pre-commit install
pre-commit run --all-files
```

The first run takes a few minutes while it builds the hook environments. **`fix end of files` shows "Failed" the first time**, because it adds missing final newlines to files such as `requirements.txt`, `Dockerfile`, `.env.example` and two SVGs. That's expected. Run it again and everything passes:

```powershell
pre-commit run --all-files   # every hook: Passed
```

The hook stays installed even when the venv isn't activated. It remembers the venv's Python.

## Step 4 — GitHub Actions

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

# A new push to the same PR cancels the run that is still going
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  backend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: docqa-backend
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.12"
          cache: pip
          cache-dependency-path: docqa-backend/requirements*.txt
      - run: pip install -r requirements-dev.txt
      - name: Lint (ruff)
        run: ruff check .
      - name: Format check (ruff)
        run: ruff format --check .
      - name: Type check (mypy)
        run: mypy app tests
      - name: Tests (pytest)
        run: pytest

  frontend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: docqa-frontend
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: docqa-frontend/package-lock.json
      - run: npm ci
      - name: Lint (eslint)
        run: npm run lint
      - name: Format check (prettier)
        run: npm run format:check
      - name: Type check (tsc)
        run: npm run typecheck
      - name: Build (vite)
        run: npm run build
```

- CI runs the same commands you ran locally. If it passes on your machine, it passes in CI.
- Node 22 matches the frontend Docker image.

## Step 8 — Require CI before merging

The "enforced" in the story means `main` can't receive code that fails CI. On GitHub, go to the repo's **Settings → Rules → Rulesets → New branch ruleset**:

- **Name:** `main`. **Enforcement:** Active.
- **Target branches:** Add target → Include default branch.
- Tick **Require a pull request before merging**.
- Tick **Require status checks to pass**, then add **`backend`** and **`frontend`**. They appear in the list after CI has run once in Step 7.
- Tick **Block force pushes**.

Then merge the PR on GitHub (**Squash and merge** keeps `main` tidy), and update locally:

```powershell
git switch main
git pull
git branch -d s0.1.3-lint-ci
```

## Common problems

| Symptom | Cause | Fix |
|---|---|---|
| `pre-commit` / `ruff` not recognised | venv not active | `docqa-backend\.venv\Scripts\Activate.ps1`, or call `.\.venv\Scripts\ruff` directly |
| `Activate.ps1 cannot be loaded` | PowerShell execution policy | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (once) |
| Commit stops with "files were modified by this hook" | A hook fixed the files for you | `git add` the changed files and commit again |
| mypy hook: `Cannot find implementation or library stub` | A new backend package isn't in the hook's environment | Add it to `additional_dependencies` in `.pre-commit-config.yaml` |
| `prettier --check` fails on files you didn't change | They were saved with CRLF | `npm run format`. In VS Code, set `"files.eol": "\n"` |
| CI `npm ci` fails: lock file out of sync | `package.json` changed without the lock file | Run `npm install` locally and commit `package-lock.json` |
| `backend`/`frontend` not listed under required checks | CI hasn't run on GitHub yet | Push the PR first (Step 7), then edit the ruleset |
| Frontend container errors after the change | Old `node_modules` volume | `docker compose up -d --build --renew-anon-volumes frontend` |
